# Hosted AI research

Hosted OpenAI API research uses a shared US$10 monthly ceiling. The deployed workflow
is enabled with restricted workload identity and durable budget reservations. During
restoration, keep paid execution disabled until access, billing controls and live
publication are verified; passing fixture tests alone is not evidence of activation.

## What runs where

The company repository owns the only AI credential and budget ledger. Daily at
07:30 Europe/London it searches approved public sources, fetches dated evidence,
drafts a structured sentiment/source review and asks a separate AI call to check it.
On Mondays at13:15 it researches the next missing complete Monday–Sunday reporting
week and validates a weekly brief. GitHub can delay starts. The weekly repository
consumes the approved public packet at14:45 Monday/Tuesday, renders the complete
HTML/PDF/map package, preserves archives, deploys and checks every live file.

The weekly repository has no AI credential and neither workflow has a cross-repository
personal token. Each writes only its own repository using its short-lived GITHUB_TOKEN.
Existing events collection and heat/site checks remain independent. Old desktop/Grok
jobs remain paused. No email is sent by this code.

## Evidence controls and limits

Search is limited to configured public publishers. The collector checks HTTPS hosts,
redirects, response completeness, publication-date passages, source text and hashes.
The first AI has only web search and structured text output. The separate reviewer
sees the fetched evidence and candidate, with no write, shell or browsing tool.
An approval receipt is generated by trusted code only after every review check passes.
Deterministic validation then checks citations, numbers, geography, all37states/FCT
and six zones, immutable dates, archives, source-use word limits and rendered PDFs.

These checks reduce errors; AI review is not human certification or proof of exhaustive
coverage. Evidence selections can be incomplete. Missing evidence means unknown.
Original source windows and assessment dates remain separate from review dates.
State rating changes are disabled: no owner-approved classification bands exist.
National/zonal surveys are separate evidence, never state estimates. The historical
unverified X sample is preserved. A failed review retains the last good publication.

Short source excerpts, links, hashes and approved output can be public. Full fetched
articles, raw API transcripts, credentials and private account data are never in Pages
artifacts or Actions uploads. Untrusted text is escaped, not executed.

## Budget

Only this company workflow may use the dedicated OpenAI project. Set its monthly
spend limit toUS$10 and enable **Enforce hard limit**. A ChatGPT subscription does
not fund API usage. Provider hard-limit enforcement may lag slightly; the code also
commits a conservative worst-case reservation BEFORE each API request and stops if
the remaining central ledger cannot cover it. Unknown request outcomes remain reserved;
there is no automatic paid retry. Never reset the ledger to get around a stop.

Discovery and daily drafting use the pinned `gpt-5.4-mini-2026-03-17` model. Weekly
drafting uses `gpt-6.1-sol` without tools. Independent review uses a separate Sol
call; daily review may fall back to Mini if the full Sol reservation does not fit.
Weekly review requires Sol or stops. Receipts record the actual model. Each search
pass is bounded (up to 2 daily or 4 weekly calls). Weekly discovery uses one security
pass and one humanitarian/completion pass, each separately reserved and charged.
Output tokens and request sizes are bounded. A
month may stop early if evidence work is large or a request outcome is uncertain.
Prices were checked on25October2026; update reviewed tariffs when changing models/prices.

## Activation (one account setup, no Mac needed afterwards)

1. Sign in to the OpenAI API platform. Use a dedicated project named **RBM Public
   Research**, with funded API billing and a US$10 enforced monthly spend limit.
2. Prefer GitHub OIDC workload identity: map only repository
   `RBMGlobal/RBMGlobal.github.io`, `ref=refs/heads/main`, `environment=github-pages`,
   and exact `workflow_ref=RBMGlobal/RBMGlobal.github.io/.github/workflows/ai-research.yml@refs/heads/main`
   to a project service account with only Responses/model-use access. The issuer is
   `https://token.actions.githubusercontent.com`; audience `https://api.openai.com/v1`.
   Use exact repository/ref/workflow_ref/environment claims, never a wildcard owner binding.
3. Company Actions variables: `OPENAI_PROJECT_ID`, `OPENAI_IDENTITY_PROVIDER_ID`,
   `OPENAI_SERVICE_ACCOUNT_ID`, `OPENAI_WIF_AUDIENCE`. If federation is unavailable,
   use a project-restricted `OPENAI_API_KEY` Actions secret plus OPENAI_PROJECT_ID,
   and leave all federation variables empty. Never paste keys in chats, code or backups.
4. After verifying provider settings, set `OPENAI_HARD_LIMIT_CONFIRMED=10` and
   `AI_RESEARCH_ENABLED=true`. Run `AI research and source review` in **daily** mode.
   Check actual sources, retained dates, ledger charge, successful Pages deployment
   and live file equality. A test-only green run is not this acceptance evidence.
5. Run **weekly** only when a reporting week is complete. Verify the approved public
   packet. Set `AI_BRIEF_ENABLED=true` in the weekly repository and run **publish**.
   Its Pages source must be GitHub Actions. Verify live HTML/PDF/archive hashes.
6. Keep retired desktop publishers paused; remove temporary verification follow-ups
   after their recorded acceptance checks are complete. Failures appear in GitHub Actions; GitHub's
   account notification preferences control whether GitHub itself sends notifications.

Creating the API service-account access or credential can require the owner's
confirmation/sign-in. Access values and billing settings are deliberately excluded
from source backups and must be reconfigured after restoring repositories.

## Recovery

- `validate` mode uses synthetic fixtures, no API calls or publication.
- Company maintenance **redeploy** restores the last committed complete site.
- Weekly **redeploy** restores the accepted report without further AI cost.
- An uncertain ledger entry requires checking the provider's usage before a reviewed
  reconciliation commit. A new workflow run is not a safe automatic retry.
- For an operator-reviewed repair of the same issue, an exact-week
  `research/state/weekly-source-recovery.json` can preserve an earlier source list
  and its run/status hash. This skips paid discovery only: fresh retrieval, drafting,
  independent Sol review and every publication check are still required. Other weeks
  ignore the recovery record. It is not publication approval.
- If a report fails, inspect the safe run summary and source receipts; fix the cause,
  not the dates or validation rules. No fabricated filler is permitted.
